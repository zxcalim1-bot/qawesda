# skill: stairs
title: Число способов подняться по лестнице
topics: Динамическое программирование
match: STAIRS & (WAYS | COUNT)
priority: 2.6
input: n
input_desc: Одна строка: n — количество ступенек (за шаг можно подняться на 1 или 2 ступеньки).
output_desc: Количество различных способов добраться до n-й ступеньки.
understood: Лестница из n ступенек; за один шаг можно подняться на 1 или 2 ступеньки. Сколькими способами можно подняться наверх?
algorithm: ДП: ways(n) = ways(n−1) + ways(n−2)
why: Последний шаг был либо на 1 ступеньку (с n−1), либо на 2 (с n−2). Это числа Фибоначчи.
ideas: Разбор по последнему шагу; ways(0) = 1, ways(1) = 1; Связь с Фибоначчи
structures: list
links: algo:dp, algo:fibonacci
edge: n = 0: один способ — ничего не делать.
edge: n = 1: один способ.
step: Состояние: ways[i] — число способов оказаться на ступеньке i.
step: Переход: на ступеньку i попадаем с i−1 или с i−2, поэтому ways[i] = ways[i−1] + ways[i−2].
step: База: ways[0] = ways[1] = 1. Ответ — ways[n].
sample: 1 => 1
sample: 2 => 2
sample: 5 => 8
sample: 10 => 89
sample: 0 => 1

## Массив ДП
approach: dp
role: beginner
time: O(n)
memory: O(n)
idea: Заполняем ways[0..n] слева направо.
principle: Каждое значение — сумма двух предыдущих.
pros: Наглядно показывает идею ДП
cons: Память O(n)
when: Для обучения ДП.
readability: 5
```python
n = int(input())
ways = [1] * (n + 1)
for i in range(2, n + 1):
    ways[i] = ways[i - 1] + ways[i - 2]
print(ways[n])
```

## Две переменные
approach: vars
role: efficient
time: O(n)
memory: O(1)
idea: Нужны только два последних значения.
principle: a, b = b, a + b сдвигает окно.
pros: O(1) памяти
cons: —
when: Обычно.
readability: 5
```python
n = int(input())
a, b = 1, 1
for _ in range(n - 1):
    a, b = b, a + b
print(b if n >= 1 else 1)
```

## Рекурсия с мемоизацией
approach: memo
role: alternative
time: O(n)
memory: O(n)
idea: ways(n) = ways(n−1) + ways(n−2) с кэшем.
principle: Без кэша время экспоненциальное — одни и те же значения считаются много раз.
pros: Прямая запись формулы
cons: Глубина рекурсии
when: Для объяснения «сверху вниз».
readability: 4
```python
from functools import lru_cache
import sys

sys.setrecursionlimit(10000)


@lru_cache(maxsize=None)
def ways(n):
    return 1 if n <= 1 else ways(n - 1) + ways(n - 2)


print(ways(int(input())))
```

# skill: coin_min
title: Минимальное число монет для суммы
topics: Динамическое программирование
match: (COIN & MIN | MINIMUM_COINS) & !WAYS
priority: 2.6
input: count | list | x
input_desc: Первая строка: k — число номиналов. Вторая: k номиналов. Третья: сумма S.
output_desc: Минимальное число монет для суммы S (монет каждого номинала сколько угодно) или -1.
understood: Даны номиналы монет (каждого — неограниченно) и сумма S. Набрать S минимальным количеством монет.
algorithm: ДП по сумме
why: dp[s] = 1 + min(dp[s − c]) по всем монетам c ≤ s. Жадный выбор крупных монет не всегда оптимален (например, монеты 1, 3, 4 и сумма 6).
ideas: dp[0] = 0; Жадность не работает для произвольных номиналов; BFS по суммам
structures: list
links: algo:dp, algo:coin-change, algo:greedy
edge: S = 0: ответ 0.
edge: Сумму невозможно набрать: -1.
edge: Пример против жадности: монеты 1 3 4, S = 6 → 2 (3 + 3), а не 3 (4 + 1 + 1).
sample: 3\n1 3 4\n6 => 2
sample: 1\n2\n3 => -1
sample: 3\n1 5 10\n0 => 0
sample: 3\n2 5 10\n27 => 4

## ДП снизу вверх
approach: dp
role: beginner
time: O(S · k)
memory: O(S)
idea: Для каждой суммы от 1 до S перебираем последнюю монету.
principle: dp[s] = min(dp[s − c] + 1). INF означает «нельзя набрать».
pros: Классическое ДП
cons: O(S · k)
when: Обычно.
readability: 5
```python
k = int(input())
coins = list(map(int, input().split()))
s = int(input())
INF = float("inf")
dp = [0] + [INF] * s
for total in range(1, s + 1):
    for c in coins:
        if c <= total and dp[total - c] + 1 < dp[total]:
            dp[total] = dp[total - c] + 1
print(dp[s] if dp[s] != INF else -1)
```

## BFS по суммам
approach: bfs
role: alternative
time: O(S · k)
memory: O(S)
idea: Каждая монета — ребро «сумма → сумма + c»; минимум монет = кратчайший путь из 0 в S.
principle: Обход в ширину находит путь с минимальным числом рёбер.
pros: Показывает связь ДП и графов
cons: —
when: Для понимания кратчайших путей.
readability: 4
```python
from collections import deque

k = int(input())
coins = list(map(int, input().split()))
s = int(input())
dist = [-1] * (s + 1)
dist[0] = 0
queue = deque([0])
while queue:
    v = queue.popleft()
    for c in coins:
        u = v + c
        if u <= s and dist[u] == -1:
            dist[u] = dist[v] + 1
            queue.append(u)
print(dist[s])
```

## Рекурсия с мемоизацией
approach: memo
role: alternative
time: O(S · k)
memory: O(S)
idea: best(s) = 1 + min(best(s − c)).
principle: lru_cache хранит результаты для каждой суммы.
pros: Прямая формула
cons: Глубина рекурсии до S
when: Для небольших S.
readability: 4
```python
from functools import lru_cache
import sys

sys.setrecursionlimit(100000)
k = int(input())
coins = list(map(int, input().split()))
s = int(input())


@lru_cache(maxsize=None)
def best(total):
    if total == 0:
        return 0
    options = [best(total - c) for c in coins if c <= total]
    options = [x for x in options if x >= 0]
    return min(options) + 1 if options else -1


print(best(s))
```

# skill: coin_ways
title: Число способов набрать сумму монетами
topics: Динамическое программирование; Комбинаторика
match: COIN & WAYS
priority: 2.6
input: count | list | x
input_desc: Первая строка: k. Вторая: k различных номиналов. Третья: сумма S.
output_desc: Количество способов набрать S (порядок монет не важен).
understood: Даны номиналы монет и сумма S. Сколькими способами можно набрать S (наборы, отличающиеся только порядком, считаются одинаковыми)?
algorithm: ДП «монета за монетой»
why: Внешний цикл по монетам гарантирует, что каждый набор считается один раз (без учёта порядка).
ideas: dp[0] = 1; Порядок циклов: монеты снаружи — сочетания, суммы снаружи — размещения
structures: list
links: algo:dp, algo:coin-change
edge: S = 0: один способ (пустой набор).
sample: 3\n1 2 5\n5 => 4
sample: 1\n2\n3 => 0
sample: 1\n10\n0 => 1
sample: 4\n2 5 3 6\n10 => 5

## Одномерное ДП
approach: dp
role: efficient
time: O(S · k)
memory: O(S)
idea: Для каждой монеты c: dp[s] += dp[s − c].
principle: После обработки первых монет dp[s] — число способов набрать s ими.
pros: Коротко и быстро
cons: Нужно понимать порядок циклов
when: Обычно.
readability: 4
```python
k = int(input())
coins = list(map(int, input().split()))
s = int(input())
dp = [1] + [0] * s
for c in coins:
    for total in range(c, s + 1):
        dp[total] += dp[total - c]
print(dp[s])
```

## Двумерная таблица
approach: dp2
role: beginner
time: O(S · k)
memory: O(S · k)
idea: dp[i][s] — способы набрать s первыми i монетами.
principle: dp[i][s] = dp[i−1][s] (не берём i-ю) + dp[i][s − c] (берём ещё одну).
pros: Наглядный переход
cons: Больше памяти
when: Для понимания ДП.
readability: 4
```python
k = int(input())
coins = list(map(int, input().split()))
s = int(input())
dp = [[0] * (s + 1) for _ in range(k + 1)]
for i in range(k + 1):
    dp[i][0] = 1
for i in range(1, k + 1):
    c = coins[i - 1]
    for total in range(1, s + 1):
        dp[i][total] = dp[i - 1][total] + (dp[i][total - c] if total >= c else 0)
print(dp[k][s])
```

## Рекурсия с мемоизацией
approach: memo
role: alternative
time: O(S · k)
memory: O(S · k)
idea: count(i, s) — способы набрать s монетами с индексами ≥ i.
principle: Либо берём монету i (остаёмся на i), либо переходим к i + 1.
pros: Естественная формулировка
cons: Глубина рекурсии
when: Для небольших входов.
readability: 4
```python
from functools import lru_cache
import sys

sys.setrecursionlimit(100000)
k = int(input())
coins = list(map(int, input().split()))
s = int(input())


@lru_cache(maxsize=None)
def count(i, total):
    if total == 0:
        return 1
    if i == k or total < 0:
        return 0
    return count(i, total - coins[i]) + count(i + 1, total)


print(count(0, s))
```

# skill: knapsack
title: Рюкзак 0/1
topics: Динамическое программирование
match: KNAPSACK | (WEIGHT & VALUE & MAX)
priority: 2.6
input_desc: Первая строка: n и W. Далее n строк «вес стоимость».
output_desc: Наибольшая суммарная стоимость предметов с суммарным весом не больше W (каждый предмет — не более одного раза).
understood: Даны n предметов с весами и стоимостями и рюкзак вместимостью W. Выбрать предметы с максимальной стоимостью, не превысив вместимость.
algorithm: ДП по вместимости
why: dp[w] — лучшая стоимость при весе не больше w; предмет добавляется, идя по w справа налево, чтобы не взять его дважды.
ideas: dp[i][w] = max(dp[i−1][w], dp[i−1][w−вес] + цена); Обход w справа налево в одномерном ДП
structures: list
links: algo:knapsack, algo:dp
edge: Предмет тяжелее W не помещается.
edge: W = 0: ответ 0.
sample: 3 50\n10 60\n20 100\n30 120 => 220
sample: 1 5\n10 100 => 0
sample: 4 7\n1 1\n3 4\n4 5\n5 7 => 9

## Двумерная таблица
approach: dp2
role: beginner
time: O(n · W)
memory: O(n · W)
idea: dp[i][w] — лучшая стоимость из первых i предметов при вместимости w.
principle: Либо не берём i-й предмет, либо берём и уменьшаем вместимость.
pros: Можно восстановить набор предметов
cons: Память O(n · W)
when: Для обучения.
readability: 4
```python
n, cap = map(int, input().split())
items = [tuple(map(int, input().split())) for _ in range(n)]
dp = [[0] * (cap + 1) for _ in range(n + 1)]
for i in range(1, n + 1):
    wt, val = items[i - 1]
    for w in range(cap + 1):
        dp[i][w] = dp[i - 1][w]
        if wt <= w:
            dp[i][w] = max(dp[i][w], dp[i - 1][w - wt] + val)
print(dp[n][cap])
```

## Одномерное ДП
approach: dp1
role: efficient
time: O(n · W)
memory: O(W)
idea: Одна строка таблицы, обход w справа налево.
principle: Справа налево dp[w − вес] ещё содержит значение «без текущего предмета» — предмет не берётся дважды.
pros: O(W) памяти
cons: Нельзя напрямую восстановить набор
when: Обычно.
readability: 4
```python
n, cap = map(int, input().split())
dp = [0] * (cap + 1)
for _ in range(n):
    wt, val = map(int, input().split())
    for w in range(cap, wt - 1, -1):
        dp[w] = max(dp[w], dp[w - wt] + val)
print(dp[cap])
```

## Рекурсия с мемоизацией
approach: memo
role: alternative
time: O(n · W)
memory: O(n · W)
idea: best(i, w) — лучший результат для предметов с i-го при вместимости w.
principle: max(не брать, взять) с кэшем.
pros: Естественная формулировка
cons: Глубина рекурсии n
when: Для небольших n.
readability: 4
```python
from functools import lru_cache
import sys

sys.setrecursionlimit(10000)
n, cap = map(int, input().split())
items = [tuple(map(int, input().split())) for _ in range(n)]


@lru_cache(maxsize=None)
def best(i, w):
    if i == n:
        return 0
    wt, val = items[i]
    result = best(i + 1, w)
    if wt <= w:
        result = max(result, best(i + 1, w - wt) + val)
    return result


print(best(0, cap))
```

## Перебор подмножеств
approach: brute
role: alternative
time: O(2ⁿ · n)
memory: O(1)
idea: Перебираем все 2ⁿ наборов битовой маской.
principle: Бит i маски = 1 означает «предмет i взят».
pros: Очевидно правильно
cons: Только для n ≤ 20
when: Для проверки и маленьких n.
readability: 4
```python
n, cap = map(int, input().split())
items = [tuple(map(int, input().split())) for _ in range(n)]
best = 0
for mask in range(1 << n):
    w = v = 0
    for i in range(n):
        if mask >> i & 1:
            w += items[i][0]
            v += items[i][1]
    if w <= cap:
        best = max(best, v)
print(best)
```

# skill: lcs
title: Наибольшая общая подпоследовательность
topics: Динамическое программирование; Строки
match: (LONGEST | MAX) & COMMON & SUBSEQUENCE
priority: 2.6
input: str | str
input_desc: Две строки.
output_desc: Длина наибольшей общей подпоследовательности.
understood: Даны две строки. Найти длину их наибольшей общей подпоследовательности (символы не обязательно подряд).
algorithm: ДП по префиксам
why: dp[i][j] — LCS префиксов длины i и j: если a[i−1] == b[j−1], то dp[i−1][j−1] + 1, иначе max(dp[i−1][j], dp[i][j−1]).
ideas: Таблица (n+1)×(m+1); Экономия памяти двумя строками
structures: list[list]
links: algo:lcs, algo:dp
edge: Одна из строк пустая — 0.
sample: abcde\nace => 3
sample: abc\ndef => 0
sample: AGGTAB\nGXTXAYB => 4

## Таблица ДП
approach: dp2
role: beginner
time: O(n · m)
memory: O(n · m)
idea: Заполняем таблицу по префиксам строк.
principle: Совпадение последних символов увеличивает ответ на 1, иначе отбрасываем символ одной из строк.
pros: Можно восстановить саму подпоследовательность
cons: Память O(n·m)
when: Для обучения.
readability: 4
```python
a = input()
b = input()
n, m = len(a), len(b)
dp = [[0] * (m + 1) for _ in range(n + 1)]
for i in range(1, n + 1):
    for j in range(1, m + 1):
        if a[i - 1] == b[j - 1]:
            dp[i][j] = dp[i - 1][j - 1] + 1
        else:
            dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
print(dp[n][m])
```

## Две строки таблицы
approach: rolling
role: efficient
time: O(n · m)
memory: O(m)
idea: Для строки i нужна только строка i − 1.
principle: prev и cur переключаются после каждой строки.
pros: O(m) памяти
cons: Нельзя восстановить ответ
when: Для длинных строк.
readability: 4
```python
a = input()
b = input()
prev = [0] * (len(b) + 1)
for ch in a:
    cur = [0]
    for j, ch2 in enumerate(b):
        cur.append(prev[j] + 1 if ch == ch2 else max(prev[j + 1], cur[j]))
    prev = cur
print(prev[-1])
```

## Рекурсия с мемоизацией
approach: memo
role: alternative
time: O(n · m)
memory: O(n · m)
idea: lcs(i, j) для суффиксов строк.
principle: Совпали первые символы — 1 + lcs(i+1, j+1), иначе максимум из двух вариантов.
pros: Прямая формула
cons: Глубина рекурсии до n + m
when: Для коротких строк.
readability: 4
```python
from functools import lru_cache
import sys

sys.setrecursionlimit(10000)
a = input()
b = input()


@lru_cache(maxsize=None)
def lcs(i, j):
    if i == len(a) or j == len(b):
        return 0
    if a[i] == b[j]:
        return 1 + lcs(i + 1, j + 1)
    return max(lcs(i + 1, j), lcs(i, j + 1))


print(lcs(0, 0))
```

# skill: edit_distance
title: Редакционное расстояние (Левенштейн)
topics: Динамическое программирование; Строки
match: EDIT_DISTANCE
priority: 2.6
input: str | str
input_desc: Две строки.
output_desc: Минимальное число вставок, удалений и замен символов, превращающих первую строку во вторую.
understood: Даны две строки. Найти минимальное число операций (вставка, удаление, замена символа), чтобы превратить первую во вторую.
algorithm: ДП Вагнера–Фишера
why: dp[i][j] = расстояние между префиксами; последний шаг — удаление, вставка или замена (бесплатно, если символы равны).
ideas: dp[i][0] = i, dp[0][j] = j; Три перехода
structures: list[list]
links: algo:edit-distance, algo:dp
edge: Одна строка пустая — длина другой.
sample: kitten\nsitting => 3
sample: abc\nabc => 0
sample: intention\nexecution => 5
sample: a\nb => 1

## Таблица ДП
approach: dp2
role: beginner
time: O(n · m)
memory: O(n · m)
idea: Заполняем таблицу расстояний между префиксами.
principle: min(удалить a[i], вставить b[j], заменить/совпало).
pros: Классика
cons: O(n·m) памяти
when: Для обучения.
readability: 4
```python
a = input()
b = input()
n, m = len(a), len(b)
dp = [[0] * (m + 1) for _ in range(n + 1)]
for i in range(n + 1):
    dp[i][0] = i
for j in range(m + 1):
    dp[0][j] = j
for i in range(1, n + 1):
    for j in range(1, m + 1):
        cost = 0 if a[i - 1] == b[j - 1] else 1
        dp[i][j] = min(dp[i - 1][j] + 1, dp[i][j - 1] + 1, dp[i - 1][j - 1] + cost)
print(dp[n][m])
```

## Одна строка таблицы
approach: rolling
role: efficient
time: O(n · m)
memory: O(m)
idea: Храним только предыдущую строку.
principle: cur[j] зависит от prev[j], cur[j−1] и prev[j−1].
pros: O(m) памяти
cons: —
when: Для длинных строк.
readability: 4
```python
a = input()
b = input()
prev = list(range(len(b) + 1))
for i, ch in enumerate(a, 1):
    cur = [i]
    for j, ch2 in enumerate(b, 1):
        cur.append(min(prev[j] + 1, cur[j - 1] + 1, prev[j - 1] + (ch != ch2)))

print(prev[-1])
```

## Рекурсия с мемоизацией
approach: memo
role: alternative
time: O(n · m)
memory: O(n · m)
idea: dist(i, j) для суффиксов.
principle: Совпадение — переходим дальше бесплатно; иначе 1 + min из трёх операций.
pros: Прямая формула
cons: Рекурсия
when: Для коротких строк.
readability: 4

## Рекурсия с мемоизацией
approach: memo
role: alternative

idea: best(i, j) = a[i][j] + {FN}(best(i−1, j), best(i, j−1)).

## Расширение от центра
approach: center
role: efficient
time: O(n²)
memory: O(1)
idea: Для каждого центра расширяем, пока символы по краям совпадают.
principle: Центр i (нечётная длина) и промежуток i, i+1 (чётная длина).

```python
            l -= 1
            r += 1
```
